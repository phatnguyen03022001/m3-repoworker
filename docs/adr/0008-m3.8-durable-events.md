# ADR 0008: Durable runs, events, artifacts, and checkpoints

## Status

Accepted for M3.8.

## Decision

Use a private SQLite event store as the durable replay boundary. Runs carry the
repository, generation, candidate snapshot, environment, policy, and lifecycle
identity. Each run has a monotonically increasing event sequence, so clients
resume logs with an explicit `after` cursor instead of relying on timestamps.
Event and checkpoint payloads must be bounded valid JSON and reject obvious
credential material.

Artifacts are copied into the private state root through an atomic temporary
file, then indexed by content digest and size. Reads enforce path containment,
regular-file status, size, and digest. Checkpoints are immutable records tied
to the run and its candidate/environment/policy identities.

Retention GC deletes only terminal runs older than the caller's cutoff and
removes their cascaded events, checkpoints, and artifact files. Startup and
replay use SQLite integrity checks. An FSEvents-style adapter may mark paths
stale, but it is only an invalidation hint; it cannot advance a snapshot or
replace digest verification.

## Consequences

- Restart replay is deterministic and bounded by a sequence cursor.
- Artifact corruption is detected before data is returned.
- GC is explicit and auditable rather than an implicit filesystem cleanup.
- A future autonomous loop can resume from a checkpoint without treating
  notifications or wall-clock ordering as authority.
