# ADR 0010: Verified, dry-run-first publication adapters

## Status

Accepted for M3.10.

## Decision

Expose fixed adapters for local Git and jj checkpoints, Git push, GitHub PRs
via `gh`, releases, Dagger, and Dagu. Adapters receive a candidate that includes a
verified snapshot, environment, and policy binding. The snapshot provider is
called immediately before every operation and after mutations; a mismatch
fails closed.

All adapters default to dry-run. External mutation additionally requires the
adapter to be enabled, the external-mutation gate, and an exact one-use
confirmation token supplied out of band. Local Git checkpoints have a separate
local-mutation gate. Git push performs `ls-remote` against the requested ref
immediately before pushing and rejects a remote-ref race. Commands are fixed
per adapter and credentials never appear in arguments.

The Dagger and Dagu integrations are intentionally thin command adapters;
their workflow semantics remain owned by those tools. No real external push,
PR, release, or deployment is performed by repository tests.

## Consequences

- Publication is reviewable through deterministic dry-run command plans.
- A stale candidate or remote ref cannot silently publish.
- External credentials remain outside the core publication contract.
- Local bare Git remotes provide integration coverage without mutating a real
  remote service.
