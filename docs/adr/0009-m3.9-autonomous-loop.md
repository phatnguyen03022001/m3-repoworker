# ADR 0009: Fixed autonomous coding loop

## Status

Accepted for M3.9.

## Decision

Implement one typed controller with the phases `inspect`, `hypothesis`,
`plan`, `parallel_commands`, `patch_candidate`, `targeted_test`,
`diagnose_retry`, `full_verify`, and `checkpoint`. Each transition is an
append-only `loop.state` event in the M3.8 event store. Restart replays those
events and resumes from the last durable phase.

The model supplies a bounded hypothesis and a typed, candidate-bound plan. A
local `Authority` interface owns every execution operation. The controller
does not interpret model text as shell commands and rejects plans whose
repository, candidate snapshot, environment, or policy binding differs from
the run. Destructive or ambiguous plans require a human checkpoint.

Failures are classified as cancellation, timeout, or execution failures. The
controller persists failed action fingerprints and permits only a bounded
number of retries; a diagnosis that proposes an identical failed action is
rejected as retry exhaustion.

## Consequences

- Crash recovery is deterministic at a phase boundary.
- Local authority remains the source of truth for filesystem and verification
  effects.
- Retry behavior converges instead of looping on an identical failed action.
- The loop is intentionally not a generic workflow DSL.
